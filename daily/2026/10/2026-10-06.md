### 코딩테스트
- Minimum Size Subarray Sum
    - 문제 정리
        > 합이 Target이상인 연속된 부분 배열의 최소 길이
    - 접근방법
        - "연속된 부분 배열" + "Target 이상" => Sliding Window
    - 구현
        ```cpp
        class Solution {
        public:
            int minSubArrayLen(int target, vector<int>& nums) {
                int l = 0;
                int r = 0;
                int sum = 0;

                int ret = 987654321;
                for(int r = 0; r < nums.size(); r++){
                    sum += nums[r];

                    while(sum >= target){
                        ret = min(ret, r - l + 1);
                        sum -= nums[l++];
                    }
                }
                return ret == 987654321? 0:ret;
            }
        };
        ```

- 유사한 문제들에 대한 풀이 방법 정리
    - 연속 + 양수 + 구간 합 조건 -> **Sliding Window**
    - 연속 + 양수/음수
        - sum == target 존재/개수 -> **PrefixSum** + **Hash**
            ```cpp
            if (mp.count(sum - target)) {
                count += mp[sum - target];
            }
            ```
        - sum >= target의 최소 길이 -> **PrefixSum** + **Monotonic Deque**
            > 어떻게 보면 Sliding Window랑 비슷하다
            ```cpp
            for (int r = 0; r <= n; r++) {
                // 현재 r에서 조건을 만족하는 l 후보들 처리
                while (!dq.empty() && prefix[r] - prefix[dq.front()] >= k) {
                    ans = min(ans, r - dq.front());
                    dq.pop_front();
                }

                // 현재 r보다 prefix 값이 크거나 같은 후보는 제거
                while (!dq.empty() && prefix[dq.back()] >= prefix[r]) {
                    dq.pop_back();
                }

                dq.push_back(r);
            }

            return ans == n + 1 ? -1 : ans;
            ```
    - 비연속
        - N이 작다 -> **Back Tracking**
        - 값들이 양수이고, Target이 크지 않다 -> **Subset Sum DP**
            ```cpp
            for (int x : nums) {
                for (int s = target; s >= x; s--) {
                    dp[s] = dp[s] || dp[s - x];
                }
            }
            ```
        - N이 40 안팎인데, Target이 너무 크다 -> **Meet in the Middle**

- 행렬 공부
    - 행렬식 (Determinant, det)
        - det(A) = 0이면 역행렬이 존재하지 않는다
    - 행렬곱
        - 교환 법칙이 성립하지 않는다
    - 단위 행렬
        - 숫자의 1과 비슷한 행렬
        - 곱해도 대상이 변하지 않는다
    - 전치 행렬
        - 행과 열을 바꾼다
    - 역행렬
        - 어떤 행렬과 곱했을때 단위 행렬(I)가 나오는 행렬
    - 동차 좌표
        > 기존 좌표에 한차원을 추가해서 일관되게 표현하는 방식
        - Why?
            - 좌표에서 회전과 스케일을 연산할때는 문제가 없지만, 이동연산을 할때는 현재 좌표 표기만으로는 부족하다
            - 행렬곱의 특성에 의해 결과값에 x, y, z가 복합적으로 나오기 때문!
            - 따라서 하나의 차원을 추가한다 (w)
                - 이를 통해 상수값을 x, y, z값과 섞이지 않고 더할 수 있게된다
        - 점을 표현할 때는 w를 1로하고, 방향벡터를 표현할 때는 w를 0으로 한다
            - w = 1, 이동 연산 가능
            - w = 0, 이동 연산 불가
        - P' = TRSP
            - 행렬 곱은 교환 법칙이 적용안되기 때문에, 순서가 중요하다
            - 일반적으로 스케일 -> 회전 -> 이동 순으로 계산한다
