            - 하지만 시작점과 도착점을 상태로 관리하면 O(N²)의 공간이 필요하므로 제한상 사용할 수 없다.
        2. ~~생각이 안남~~
    - 일단 구현해보자
        > Brute Force
        ```cpp
        class Solution {
        private:
            int n;
            bool dfs(vector<int>& gas, vector<int>& cost, int start, int cur, int g, bool flag){
                // 예외처리
                if(g < 0) return false;
                if(flag && start == cur)return true;
                // get Gas
                g += gas[cur];
                // move
                g -= cost[cur];
                return dfs(gas,cost,start,(cur+1)%n,g,true);
            }
        public:
            int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
                n = gas.size();
                for(int i = 0;i<n;i++){
                    if(dfs(gas,cost,i,i,0,false)) return i;
                }
                return -1;
            }
        };
        ```
    - 힌트를 보았다
        1. Greedy
        2. start에서 출발해서 i까지 갔는데 결국 기름이 부족했다면, start ~ i 사이의 다른 주유소에서 출발하면 i를 넘어갈 수 있을까?
    - 그래도 감이 잡히지 않아서 정답 코드를 보았음
        ```cpp
        class Solution {
        public:
            int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
                int total = 0;
                int tank = 0;
                int start = 0;

                for (int i = 0; i < gas.size(); i++) {
                    int diff = gas[i] - cost[i];

                    total += diff;
                    tank += diff;

                    if (tank < 0) {
                        start = i + 1;
                        tank = 0;
                    }
                }

                return total >= 0 ? start : -1;
            }
        };
        ```
        > 여기서 핵심은 '처음부터 살펴보는데, "Skip한다"'이다
        > Brute Force로 모든 경우의 수를 살펴보는 것이 아니라, 불가능한 경우에 대해서는 Skip해서 연산 수를 줄인다
- Jump Game
    - 접근 방법
        - Brute Force
            - 어떤 경우의 수가 있는가?
                - 현재 위치에서 갈 수 있는 모든 위치에 대해 계산한다
            - 모든 경우를 계산 해야하는가?
                - 다음 위치와 그 위치에서 갈 수 있는 최대 높이를 이용해 최대값만 구하자
                - 최대값이 아닌 경우는 이미 해당 최대값을 통해 갈 수 있으므로 별도로 계산하지 않아도 된다
        > "Greedy"
    - 구현
        ```cpp
        class Solution {
        public:
            bool canJump(vector<int>& nums) {
                if(nums.size()==1)return true;

                int s = 0;
                while(true){
                    int maxJump = nums[s];

                    int farthest = s;
                    int farthestIdx = s;
                    for(int i = 1; i <= maxJump; i++){
                        int next = s + i;
                        int dist = nums[next];
                        if(next + dist >= nums.size()-1) return true;

                        if(farthest < next + dist){
                            farthest = next + dist;
                            farthestIdx = next;
                        }
                    }
                    if(farthestIdx == s) break;
                    s = farthestIdx;
                }
                return false;
            }
        };
        ```
    - 최적화
        > 힌트를 보았다
        > - 최대값이 아닌 경우는 이미 해당 최대값을 통해 갈 수 있으므로 별도로 계산하지 않아도 된다.
        > - 여기서 굳이 **"다음으로 이동할 최적의 위치"**를 고를 필요도 없다
        1. 지금까지 도달 가능한 모든 위치를 이용해, 최대 도달 가능 위치 farthest를 갱신한다
            1. 각 위치에 도달 가능한가? Yes -> 계산 / No -> false
            2. 각 위치에서 마지막 인덱스에 접근 가능한가? Yes -> true / No -> 다음 Index 계산
    - 회고
        - 첫 접근
            > 다음에 어디로 점프하는게 가장 좋을까?
        - 최적화
            > 어디로 점프할지는 중요하지 않고, 현재 어디까지 도달가능한지만 알면 된다

### CS공부
- FixedUpdate에 대한 고찰
    1. FixedUpdate란?
        - Time.fixedDeltaTime을 기준으로 고정된 게임 시간 간격을 시뮬레이션하기 위한 Update 함수
        - 기본 fixedDeltaTime은 0.02초 → 초당 50번의 Fixed Step
        - 고정된 시간 간격으로 시뮬레이션하기 때문에 물리 연산에 적합
        - **기본 물리 Simulation Mode에서는 FixedUpdate 직후 물리 시뮬레이션이 수행된다**
    2. 호출 방법
        - Unity는 경과한 게임 시간을 확인한다
        - 누적된 시간이 fixedDeltaTime 이상이면 Fixed Step을 수행한다
        - 필요한 Fixed Step 수만큼 FixedUpdate를 호출한다
    3. 프레임 간격이 길어 여러 개의 FixedUpdate가 필요하다면?
        - 지나간 게임 시간을 따라잡기 위해 한 렌더 프레임에서 FixedUpdate를 여러 번 호출한다
    4. 이로 인한 문제점은?
        - 한 프레임에 많은 FixedUpdate + Physics Simulation이 몰릴 수 있다
        - 물리 연산 때문에 프레임 처리 시간이 더 길어질 수 있다
        - 프레임이 더 늦어지면서 다음 프레임에서 처리해야 할 Fixed Step도 증가할 수 있다
    5. 이를 해결하기 위한 방법은?
        - Time.maximumDeltaTime으로 한 프레임에서 물리 시스템이 따라잡으려고 처리할 수 있는 시간에 상한을 둔다
        - 한 프레임에 지나치게 많은 Fixed Step이 몰리는 것을 방지한다
        - 제한을 넘어선 경우 해당 시간을 전부 물리적으로 따라잡지 않기 때문에 물리 시뮬레이션이 실제 시간보다 잠시 느려지는 것을 감수한다
