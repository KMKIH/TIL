### 코딩테스트
- Task Scheduler
    - 문제 요약
        - CPU는 작업을 수행하거나 idle 상태가 될 수 있다
        - 같은 작업을 하기 위해서는 n의 간격이 필요하다
    - 초기 접근
        - 그리디?
            - 작업이 많은 순서
                - 많은 작업인 것을 처리해야 나중에 idle을 사용하지 않을 수 있다
            - 작업이 가장 많지만, 현재 처리 불가능한 것들은 나중에 처리해야한다
    - 1차 구현
        ```cpp
        priority_queue<pair<int,int>> pq; // <count, -lastTime>
        queue<pair<int,int>> tmp;
        ```
    - 1차 회고
        - 단순 queue로해서 모든 작업을 다시 pq로 넣으면 


    - 2차 구현
        ```cpp
        priority_queue<pair<int,int>> pq1; // <count, -lastTime> 
        priority_queue<pair<int,int>> pq2; // <-lastTime, count>
        ```
    - 2차회고
        > 자료구조를 사용하면, 그에 대한 명확한 정의가 필요하다
        - pq1: 현재 실행 가능한 작업 목록
        - pq2: 아직 쿨다운 중인 작업 목록

        (최종 수도 코드)
        ```cpp
        // 현재 시간에 실행 가능해진 모든 작업 복귀 (pq2->pq1)
        while (!pq2.empty()) /* */

        // Idle 처리
        if (pq1.empty()) {
            curTime++;
            continue;
        }
        
        // 실행 가능한 작업 중 가장 많이 남은 작업 선택
        auto cur = pq1.top(); pq1.pop();
        int count = cur.first;

        count--;
        if (count > 0) pq2.push({-curTime, count});

        curTime++;
        ```
