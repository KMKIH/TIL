## 정리회사 과제
### 회사 과제
#### 문제 분석
- 수많은 오브젝트들이 주어질때, 최적화된 데이터 처리와 충돌처리
#### 문제 접근
1. 충돌 처리
    - RayCast나 Collider를 사용하기에는 몬스터의 수가 너무 많다
    => Grid형태를 띄는 게임이므로, 배열을 사용해 충돌 처리를 했다
2. 데이터 최적화
    - 처리 범위를 벗어난 오브젝트도 형태를 유지하는 요구사항이 있었다
    - 단순히 오브젝트 풀링을 사용할 수 없는 상황
    - 논리적 데이터와 외형을 분리하여 별도로 처리한다
        - 처리 범위를 벗어나면 논리적 데이터는 지우고, 외형만 남긴다
    - 공용으로 사용하는 로직에 대해서는 각 오브젝트에서 실행하는 것이 아니라, 별도의 매니저를 통해 해당 로직을 수행하게한다
    - 공용 데이터 (최대 Hp 등)도 별도의 데이터베이스에서 값을 가져오도록 한다

####회고

> 이전 과제를 할때에도 유사한 접근방법이 있었다

### 코딩 테스트
- Product of Array Except Self
    - 문제 요약
        - 배열에서 자신을 제외한 나머지 원소들의 곱을 나타내는 저장하자
        - 제약조건
            1. O(N)
            2. 나눗셈 사용 금지
    - 문제 접근
        - 나눗셈 사용
            - 처음에 나눗셈 사용 금지를 보지 못하고 나눗셈을 이용해서 풀었다
            - 예외처리
                - 나눗셈을 사용해야하므로, 0에 대한 예외처리가 중요하다
                - 0이 1개인 경우, 해당 위치를 제외한 정답 배열은 0이된다
                - 0이 2개 이상인 경우, 모든 정답 배열은 0이된다
            - 접근 방법
                1. 0을 제외한 모든 원소를 곱한 값을 저장한다
                2. 각 원소에 대해 곱한 값에서 자기 자신을 나눈 값을 저장한다
            ```cpp
            vector<int> ret(nums.size(),0);
            if(zeroCount > 1) return ret;
            if(zeroCount == 1) {
                ret[zeroIdx] = product;
                return ret;
            }
            for(int i = 0;i<nums.size();i++){
                ret[i] = product/nums[i];
            }
            ```
        - 나눗셈을 사용하지 않고 접근
            - 고민
                - 가장 간단한 접근 방법
                    - O(N^2)의 시간복잡도로 각 원소에 대해서 정답 배열 구하기
                - 중복되는 경우는 없을까?
                    - 원소를 한칸씩 순회한다고 봤을때, 자신을 기준으로 좌우를 곱한다
                    - 각각의 좌 우 곱을 구할때 중복되는 경우가 있다
            - 접근 방법
                - 각각의 좌 우 곱을 저장해놓고 사용하자
                > answer[i] = left[i-1] * right[i+1]
        - 최적화
            - 좌우곱을 저장해야할까?
            1. answer[i] = left[i-1]*right[i+1] 이므로, answer에 left를 넣고 시작하자
            2. 이렇게되면, right값을 실시간으로 구하면서 답을 구할 수있다
