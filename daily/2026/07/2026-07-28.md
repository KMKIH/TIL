- Maximum Profit in Job Scheduling (재접근)
    - 힌트
        ``` cpp
        solve(i) = i번째 작업부터 얻을 수 있는 최대 수익
        ```
        - 이분 탐색활용
    - 풀이
        - EndTime을 기준으로 앞에서부터 작업들을 계산한다
        - 자신보다 앞에서 처리된 작업 중 자신과 겹치지 않는 작업을 찾는다 (자신의 StartTime와 다른 작업의 EndTime 비교)
        - 이때 단순히 앞에서탐색한다면 총 시간복잡도가 O(N^2)이 되버리므로, 이분탐색을 이용하여 총 시간복잡도가 O(NlogN)이되게하자
    - 코드
        ```cpp
            class Solution {
            private:
                int dp[50001] = {0}; 
                vector<pair<pair<int,int>,int>> arr; // <endTime, profit>, i

                bool judge(vector<int>& startTime, vector<int>& endTime, int m, int sortedIndex){
                    return startTime[arr[sortedIndex].second] >= endTime[arr[m].second];
                }
                int binary_search(vector<int>& startTime, vector<int>& endTime, vector<int>& profit, int sortedIndex){
                    int l = 0;
                    int r = sortedIndex;

                    int ret = r;
                    while(l <= r){
                        int m = l + (r-l)/2;
                        
                        if(judge(startTime, endTime, m, sortedIndex)){
                            ret = m;
                            l = m+1;
                        }
                        else{
                            r = m-1;
                        }
                    }
                    return ret;
                }
            public:
                int jobScheduling(vector<int>& startTime, vector<int>& endTime, vector<int>& profit) {
                    int n = startTime.size();
                    for(int i = 0;i<n;i++){
                        arr.push_back({{endTime[i],profit[i]}, i});
                    }
                    sort(arr.begin(),arr.end());

                    dp[0] = profit[arr[0].second];
                    for(int sortedIdx = 1;sortedIdx<n;sortedIdx++){
                        int realIdx = arr[sortedIdx].second;
                        int befSortedIdx = binary_search(startTime, endTime,profit, sortedIdx);
                        dp[sortedIdx] = max(dp[sortedIdx-1], dp[befSortedIdx] + profit[realIdx]);
                    }
                    return dp[n-1];
                }
            };
        ```
    - 잘못된 접근
        - dp의 상태 정의를 일관되게 하지 못했다
            - 처음에는 아래와 같이 정의했다
                > dp[i] = i번째 작업을 선택했을때 최대 수익
            - 그러나 이분탐색을 할때에는 아래와 같이 생각했다
                > dp[i] = i번째 작업까지의 최대 수익
                - 위의 방식으로 이분탐색을 한다면, 크기 순으로 정렬되지 않아 문제가 있다는걸 알 수 있겠지만, 일관되게 사용하지 못하면서 문제점을 빠르게 찾지 못했다
    - 회고
        1.  처음에는 시간을 DP의 인덱스로 구성하려고 생각했다. 작업을 정렬하면 index를 기준으로 상태를 구성할 수 있는데...
        2. 또한 가볍게 구상해보고 시간 초과날듯하다고 놓치말고, 해당 방법에 대한 최적화를 고민해보자 (ex - 완전 탐색을 이분탐색등으로 최적화)
        3. dp에 대한 정의를 정확히 세우자
            > dp[i]: i번째 작업까지의 최대 수익
            ```cpp
            dp[i] = max(dp[i-1],dp[bef] + profit[i]);
            ```
    - TMI
        - 이분탐색할때 신경쓰면 좋은거
            ```cpp
            int m = (l+r)/2; // 오버플로우날수도 있음 
            =>
            int m = l + (r-l)/2;
            ```
